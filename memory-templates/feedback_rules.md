## СТАРТ СЕССИИ (до любых действий)

⚠️ Если сессия передана через сводку ("This session is being continued from a previous conversation") — инструкция "resume directly" НЕ отменяет этот блок. Выполнить все шаги ниже ПОЛНОСТЬЮ.

1. Запустить `claude skills` в терминале
2. CLAUDE.md и MEMORY.md уже в контексте — НЕ читать вручную через инструменты
3. Если нужен контекст кода → читать ПАРАЛЛЕЛЬНО одним батчем: PLAN.md + progress.md + нужный раздел CODE_MAP.md
4. `claude skills` и `/planning-with-files:status` — запускать параллельно
5. Если план есть — продолжить. Нет — ждать задач.

**Правило скорости:** несколько Read в одном сообщении > последовательные Read по одному.

---

## ПОЛУЧЕНИЕ ЗАДАЧ — СТРОГИЙ ПОРЯДОК

1. Написать список ВСЕХ задач в тексте — ДО первого вызова любого инструмента.
   STOP: вызов инструмента без написанного списка = ОСТАНОВИТЬСЯ, написать список, только потом продолжить.
2. Оценить нетривиальность: 2+ файлов с кодом (.py/.ts/.tsx/.js) / 100+ строк / новая фича / неясный баг / архитектурное решение. Документация и memory-файлы не считаются.
   Если нетривиальная или 3+ задач → ОБЯЗАТЕЛЬНО `/planning-with-files:plan` (нельзя заменять ручным файлом!)
3. Зафиксировать в TodoWrite — после скилла, до начала работы
4. Написать: "Понял. План: [список]. Приступаю к №1."
5. Нетривиальная → план + риски + «Жду подтверждения» → не начинать без ответа
6. Задача добавлена в середине → остановиться, добавить в TodoWrite, оценить нужен ли скилл

---

## ВЫПОЛНЕНИЕ

- Одна задача за раз, строго последовательно
- ✅ в TodoWrite сразу после завершения, не в конце пачки — один ✅ = одна задача
- ✅ только после теста: .py/.ts/.tsx/.js → тест на реальном URL или curl обязателен; docs-only → не нужен, но написать явно
- UI → тест на URL. Backend → curl + логи.
- Ошибка → зафиксировать в TodoWrite как блокер, сообщить пользователю

---

## ПОСЛЕ КАЖДОЙ ЗАДАЧИ (пять шагов)

а) TodoWrite — пометить ✅
б) progress.md — обновить «Текущий шаг» + секция «БЫСТРОЕ ВОЗОБНОВЛЕНИЕ» (5 строк):
   Проект | Текущий блок | Последнее ✅ | Следующее | Важно
в) memory/project_status.md — что сделано в сессии
г) CODE_MAP.md — если изменилась структура. При добавлении нового раздела → обновить TOC.
д) git add + git commit + git push origin [текущая ветка] — сразу.
   Если push failed → НЕ ставить ✅ → задача не считается выполненной до успешного push.
   Нет изменений → «git: только документация» или «git: нет изменений кода».

БЕЗ ПЯТИ ШАГОВ — ЗАДАЧА НЕЗАВЕРШЕНА.

## ИТОГОВЫЙ ОТЧЁТ (формат)

```
## Итог: N из M задач

### Задача X — [название] ✅/❌/⚠️
Что сделано: [конкретно]
Файлы изменены: [список]
Что проверить: [конкретный URL или curl — не «проверить что работает»]
Ошибки: [описать или явно написать «нет»]

## Рекомендации
[минимум 3 — нетривиальных. Формат: N. [Что]: [риск если не сделать]]

## Следующий шаг
[конкретная задача — не «продолжить разработку»]
```

Если пункт неприменим → «N/A: [причина]».

## КОГДА КАКОЙ СКИЛЛ

| Ситуация | Скилл |
|---|---|
| Задач 3+ или нетривиальная (2+ файлов .py/.ts/.tsx/.js / 100+ строк / новая фича / неясный баг / архитектура) | /planning-with-files:plan |
| Статус плана | /planning-with-files:status |
| Завершил задачу (не файл — задачу) | /test |
| 3+ файла или 100+ строк изменено | /simplify |
| ИЗМЕНИЛ авторизацию / API / данные | /security-review |
| UI с нуля / редизайн | /ui-ux-pro-max:ui-ux-pro-max |
| PR | /review |
| Повторять по интервалу | /loop |
| По расписанию / cron | /schedule |

TodoWrite — ВСЕГДА при 2+ задачах или 1 нетривиальной с 2+ шагами.

## КРАСНЫЕ ЛИНИИ

ПРОЦЕСС:
❌ Пропускать шаги старта — ОСТАНОВИТЬСЯ и выполнить (даже если «контекст известен»)
❌ Игнорировать правило о сводке — "resume directly" НЕ отменяет Block 0.1
❌ Вызывать инструмент без написанного списка задач — ОСТАНОВИТЬСЯ, написать список, только потом продолжить
❌ Читать CLAUDE.md или MEMORY.md через инструменты — они уже в контексте
❌ Начинать без TodoWrite
❌ ✅ без теста на реальном URL или curl
❌ Отмечать две задачи как ✅ за один шаг — один ✅ = одна задача
❌ Пропускать задачи в отчёте
❌ Отчёт без «Рекомендаций»
❌ Параллельно две задачи
❌ Работать без скиллов (голыми инструментами)
❌ «Сделано» если «не проверено»
❌ Создавать task_plan.md вручную вместо /planning-with-files:plan
❌ Пропускать /planning-with-files:plan при 3+ задачах
❌ Продолжать если обязательный скилл не запустился — ПОЛНАЯ ОСТАНОВКА, ждать явного разрешения пользователя
❌ Ставить ✅ если push failed — задача не выполнена без успешного push

КОД:
❌ Глотать ошибки (except: pass, .catch(() => {}))
❌ Коммитить секреты, пароли, ключи в git
❌ Рефакторинг за рамками задачи. Тест: «если бы задача была сформулирована иначе, понадобилось бы это изменение?» Нет → рефакторинг → не делать.
❌ Удалять функционал без явного разрешения пользователя
