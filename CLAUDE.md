БЛОК 0.3 — ВЫПОЛНЕНИЕ ЗАДАЧ
═══════════════════════════════════════════════════════════

- Делать задачи строго по одной, последовательно.

- ✅ только после ручного теста на реальном URL или curl-проверки — код в редакторе не считается.
  ⚠️ Ручной тест (URL/curl) = верификация конкретной фичи (требование для ✅). /test скилл = smoke всей системы (обязателен дополнительно — это разные проверки).

- UI-изменения → тест на реальном URL обязателен.
- Backend-изменения → curl-запрос + проверка логов.
- Если встретил ошибку → зафиксировать в TodoWrite как блокер, сообщить пользователю.
- Если задача неясна → спросить ДО начала, не в середине.
- Задача выполнена → выполнить все шаги Блока 0.5 ПОЛНОСТЬЮ (БЕЗ ИСКЛЮЧЕНИЙ).

ФАЗА 1 — ЗАФИКСИРОВАТЬ ИСТОЧНИК (до любого кода)

Источник = URL:
1. curl / WebFetch страницы — получить реальный HTML, НЕ реконструировать из памяти
2. Записать в findings.md: все секции по порядку, все тексты дословно, все URL изображений, весь функционал (формы/попапы/квизы/анимации/кнопки)
3. Сообщить пользователю: «Нашёл [N] секций, [M] изображений. Вот структура: [список]»

Источник = скриншоты / фото / PDF:
1. Прочитать ВСЕ предоставленные файлы через Read
2. Записать в findings.md: тексты дословно, все элементы интерфейса, описание каждого изображения (что изображено, где стоит в макете)
3. Если текст нечёткий или элемент непонятен → спросить, НЕ угадывать

Источник = несколько файлов / страниц / скриншотов:
1. Обработать ВСЕ файлы до начала работы
2. Не начинать копирование пока не зафиксированы все источники

ФАЗА 2 — ПОДТВЕРЖДЕНИЕ (перед любым кодом)

Показать пользователю итог findings.md:
- Список всех секций в порядке
