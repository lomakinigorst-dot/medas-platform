### ADR-001 — Выбор frontend фреймворка: Next.js 15 App Router
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Нужен фреймворк для медицинской платформы с публичными страницами врачей (SEO критично) и личными кабинетами (интерактивный UI).

**Решение:** Next.js 15 с App Router

**Почему:**
- SSR/SSG для публичных страниц → Google индексирует каждого врача
- React Server Components → меньше JS, быстрее FCP
- Личные кабинеты → Client Components с guard-роутами
- Единый deployment через Docker

**Альтернативы:**
- Vue/Nuxt — меньше экосистема UI компонентов (shadcn/ui нет)
- SPA (CRA/Vite) — плохое SEO, придётся добавлять SSR отдельно
- Remix — меньше community, меньше UI библиотек

**Последствия:** App Router = более крутая кривая обучения, но всё в одном

### ADR-002 — Выбор backend: FastAPI
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Нужен API-сервер для логики бронирования, расписания, бонусов.

**Решение:** FastAPI (Python 3.12)

**Почему:**
- Async-first → параллельные запросы записи без блокировок
- Pydantic v2 → валидация моделей с автогенерацией OpenAPI
- SQLAlchemy 2.0 async → эффективные запросы к PostgreSQL
- Лёгкое горизонтальное масштабирование

**Альтернативы:**
- Express (Node.js) — нет строгой типизации из коробки
- Django — монолитный, ORM синхронный по умолчанию
- Rails — нет опыта в команде

**Последствия:** Два отдельных сервиса (frontend/backend), но чёткое разделение

### ADR-003 — Поиск: PostgreSQL FTS (ts_vector)
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Нужен поиск врачей по имени, специализации, городу.

**Решение:** PostgreSQL Full-Text Search с ts_vector

**Почему:**
- Нет внешних зависимостей на старте
- PostgreSQL уже в стеке
- Достаточно для 10K-100K врачей
- GIN-индекс — быстрый полнотекстовый поиск

**Альтернативы:**
- Elasticsearch — мощнее, но сложнее инфраструктура, +ресурсы на VPS
- Meilisearch — хорошо, но ещё один сервис

**Последствия:** Миграция на Elasticsearch когда > 100K записей. Запланировано в v2.

### ADR-004 — Auth: JWT + httpOnly cookies
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Три роли (пациент, клиника, врач), защищённые маршруты.

**Решение:** JWT access token (15 мин) + refresh token в httpOnly cookie (30 дней)

**Почему:**
- httpOnly cookies защищают от XSS
- Access token в memory (не localStorage) — XSS-безопасно
- Stateless JWT = легко масштабировать

**Альтернативы:**
- Supabase Auth — vendor lock-in, сложнее кастомизировать роли
- NextAuth — привязка к Next.js, сложнее с FastAPI backend
- Сессии в Redis — stateful, нужен Redis везде

**Последствия:** Нужна логика refresh на frontend (interceptor в React Query)

### ADR-005 — Monorepo (frontend/ + backend/ в одном репо)
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Один разработчик, один CI/CD.

**Решение:** Monorepo с папками frontend/ и backend/

**Почему:**
- Один PR — изменения frontend + backend вместе
- Один GitHub Actions workflow
- Проще для поддержки на начальной стадии

**Альтернативы:**
- Два репозитория — сложнее синхронизировать версии API

**Последствия:** При росте команды — split на отдельные репозитории

### ADR-006 — Бонусная система: баллы без вывода
**Дата:** 2026-06-10
**Статус:** Принято

**Контекст:** Нужно удерживать пациентов на платформе.

**Решение:** Баллы начисляются после состоявшегося визита, тратятся только внутри MEDAS

**Почему:**
- Не нужна лицензия на финансовые операции
- Удержание пациентов — возвращаются за следующей записью
- Срок жизни 12 месяцев → мотивирует тратить быстро

**Альтернативы:**
- Кэшбэк деньгами — нужна лицензия, сложная бухгалтерия
- Скидка сразу — клиника теряет маржу, нет удержания

**Последствия:** Пациент мотивирован возвращаться, клиника не теряет деньги
