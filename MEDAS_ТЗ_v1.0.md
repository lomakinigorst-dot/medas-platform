# MEDAS — Техническое задание v1.0

> Медицинский маркетплейс | saas.med-as.ru | Июнь 2026

---

## 1. Суть продукта и цель

MEDAS — медицинский маркетплейс (аналог Напоправку / СберЗдоровье). Пациент находит врача или клинику, записывается онлайн, ведёт электронную медкарту и накапливает бонусы. Клиники получают управляемый поток пациентов и инструменты аналитики. Врачи управляют расписанием и видят историю своих пациентов.

### Монетизация

- Комиссия с каждой записи через платформу (8–15%)
- Подписка для клиник: базовый / Pro / Enterprise
- Продвижение в поиске — платное поднятие в выдаче
- B2B: корпоративное медобслуживание (ДМС-интеграция)

## 2. Роли в системе

| Роль | Кто это | Что делает |
|---|---|---|
| Пациент | Конечный пользователь | Ищет врача, записывается, ведёт медкарту, копит бонусы |
| Врач | Специалист в клинике | Управляет расписанием, ведёт приёмы, пишет назначения |
| Администратор клиники | Управляет клиникой | Добавляет врачей, видит аналитику, управляет профилем |
| Контент-менеджер MEDAS | Сотрудник платформы | Наполняет каталог, проверяет клиники, пишет статьи |
| Суперадмин MEDAS | Технический администратор | Полный доступ: пользователи, клиники, настройки, финансы |
| Финансовый менеджер | Бухгалтерия / аналитика | Видит выручку, комиссии, выплаты клиникам |

## 3. Архитектура системы

### 3.1 Стек технологий

| Слой | Технология | Обоснование |
|---|---|---|
| Frontend (публичный сайт) | Next.js App Router + TypeScript + Tailwind CSS v4 | SSR для SEO профилей врачей/клиник |
| Frontend (кабинеты / админки) | Next.js App Router (тот же репозиторий, отдельные роуты) | Единый стек, переиспользование компонентов |
| Backend API | Python + FastAPI | Быстрый, async, Pydantic-валидация, OpenAPI автоматически |
| Основная БД | PostgreSQL 16 | ACID-транзакции, сложные JOIN, строгая схема |
| Кеш / очереди | Redis 7 | Кеш поисковых запросов, сессии, очереди SMS/email, rate limit |
| Полнотекстовый поиск | Elasticsearch 8 (Фаза 2) | Старт: pg_trgm; при 100k+ записей — миграция на ES |
| Файловое хранилище | S3 (Selectel / Yandex) | Фото врачей, PDF документы, анализы |
| Реверс-прокси | Nginx | SSL termination, статика, upstream к Next.js |
| Деплой | Docker + Docker Compose + VPS | Простой старт, лёгкий переезд на k8s при масштабе |
| CI/CD | GitHub Actions | Автосборка и деплой при push в main |

## 6. Функционал — детально

### 6.1 Поиск и фильтрация

- Полнотекстовый поиск по имени врача, специальности, симптому, названию клиники
- Фильтры: специальность, район/метро, цена (от-до), дата доступности, пол врача, язык, ДМС, выезд на дом, онлайн-приём
- Сортировка: по рейтингу, по цене, по ближайшей доступности
- Геопоиск: «рядом со мной» (геолокация браузера)
- Старт: pg_trgm в PostgreSQL; при 100k+ записей — миграция на Elasticsearch
- Результаты кешируются в Redis на 5 минут

### 6.2 Система записи

- Пациент выбирает врача → дату/слот → тип (клиника / онлайн / дом) → подтверждает
- Доступные слоты: doctor_schedule минус занятые appointments
- SMS-подтверждение записи — за 24 часа и за 2 часа до приёма
- Отмена: до 24 часов — бесплатно; позже — штраф
- Повторная запись в 1 клик из истории приёмов

### 6.3 Авторизация и безопасность

- JWT: access-токен 15 минут + refresh-токен 30 дней
- Основной способ входа: телефон + SMS-код (6 цифр)
- Альтернативный: email + пароль (bcrypt, salt 12)
- Разные JWT claims для каждой роли — патч на уровне middleware
- Rate limiting: не более 5 неудачных попыток входа с одного IP за 10 минут
- Медицинские данные доступны только владельцу и врачу на активном приёме

### 6.4 Электронная медкарта

- Базовые данные: ФИО, группа крови, аллергии, хронические болезни, текущие препараты
- История визитов: диагноз + назначение + заметки врача (заполняет врач после приёма)
- Загрузка документов: анализы, снимки МРТ, рецепты — PDF / JPG → S3
- Показатели здоровья: давление, вес, пульс — вручную или из приложения
- Семейный профиль: управление медкартами до 5 членов семьи
- Экспорт в PDF
- QR-код для передачи врачу — временный токен на 24 часа

### 6.5 Бонусная программа

| Уровень | Накопленные баллы | Кешбэк на приём |
|---|---|---|
| Bronze | 0 – 999 | 5% |
| Silver | 1 000 – 4 999 | 7% |
| Gold | 5 000 – 14 999 | 10% |
| Platinum | 15 000+ | 12% + приоритетная запись |

- Траты: скидки на приём, бесплатные анализы, приоритетная запись
- Реферальная программа: +300 баллов за приглашённого друга, который записался
- Срок жизни баллов: 365 дней с момента начисления
- Бонусы за действия: регистрация (+500), первый отзыв (+50), заполнение медкарты (+100)

### 6.6 Уведомления

| Триггер | Канал | Кому |
|---|---|---|
| Новая запись создана | SMS + email | Пациент + Клиника |
| Запись подтверждена клиникой | SMS | Пациент |
| Напоминание за 24 часа | SMS | Пациент |
| Напоминание за 2 часа | SMS | Пациент |
| Запись отменена | SMS | Пациент + Клиника |
| Запись завершена (с просьбой отзыва) | Push | Пациент |
| Новая заявка на приём | Email | Администратор клиники |
| Бонусы начислены | Push | Пациент |
| Сертификат врача истекает (30 дней) | Email | Врач |

### 6.7 Отзывы

- Оставить отзыв можно только после состоявшегося приёма (appointment.status = done)
- Оценка от 1 до 5 + текст (минимум 20 символов)
- Модерация: автоматическая (фильтр нецензурной лексики) + ручная для спорных
- Врач / клиника могут ответить на отзыв
- Рейтинг пересчитывается автоматически после каждого нового отзыва

### 6.8 Онлайн-консультации

- Видеозвонок: интеграция Agora.io (WebRTC)
- Пациент получает ссылку за 15 минут до приёма (SMS + email)
- Врач видит медкарту пациента прямо во время звонка
- После окончания — врач заполняет назначение и закрывает приём

### 6.9 Аналитика для клиники

- Источники лидов: из поиска, из каталога, прямая ссылка, реклама
- Конверсия: просмотр профиля → запись → состоявшийся приём
- Выручка по дням / неделям / месяцам с графиком
- Загрузка врачей: % занятости по слотам
- Возвращаемость пациентов (Retention Rate)
- NPS и средний рейтинг по отзывам

## 7. Пользовательские сценарии

> Подробное описание каждого сценария — в файле `PATIENT_SCENARIOS.md`.

### 7.1 Основные пути пациента

| Сценарий | Точка входа | Конечная цель |
|---|---|---|
| Поиск клиники | /clinics, главная, Google | Запись к врачу клиники |
| Поиск конкретного врача | /search, имя в Google | Запись к выбранному специалисту |
| Поиск по симптому | Google → /articles/[slug] | Запись к врачу по специальности статьи |
| Повторный визит | ЛК → история приёмов | Запись в 1 клик к тому же врачу |
| Запись для члена семьи | ЛК → семья → запись | Запись для ребёнка/супруга |
| Реферальная ссылка | /register?ref= | Первая запись + бонусы |
| Экстренная запись | /search → «Сегодня» | Запись к ближайшему доступному врачу |
| ДМС пациент | /search → ДМС, /clinics → ДМС | Запись с оплатой по полису |

### 7.2 Общий flow уведомлений (для всех сценариев)

| Триггер | Когда | Канал | Содержание |
|---|---|---|---|
| Запись создана | Немедленно | SMS + Email | Детали: врач, дата, время, адрес |
| Напоминание | За 24 часа | SMS | Ссылка отмены |
| Напоминание | За 2 часа | SMS | Финальное напоминание |
| Прием завершён | Через 2 часа | Push | Запрос отзыва (+50 бонусов) |
| Бонусы начислены | После визита | Push + Email | Баланс обновлён |
| Повторный визит | Через 30 дней | Email | Напоминание о контроле |

### 7.3 Постvisit-flow (после каждого приёма)

1. `appointment.status = done` → ⚙️ начисление бонусов (5% от цены)
2. ⚙️ Создание записи в медкарте (врач заполняет диагноз + назначения)
3. 📱 Push через 2ч: запрос отзыва
4. 📱 Email через 24ч: «Начислено X бонусов» + «Записаться снова»
5. 📱 Email через 30 дней: «Напоминание о повторном визите»
6. Пациент оставляет отзыв → модерация → рейтинг обновляется → +50 бонусов

## 8. Безопасность и соответствие законодательству

### 8.1 Законодательство

- ФЗ-152 «О персональных данных» — шифрование, согласие на обработку, возможность удаления данных по запросу
- ФЗ-323 «Об основах охраны здоровья» — медицинские данные хранятся только в РФ
- Обязательный аудит-лог всех действий с медицинскими данными
- Форма согласия на обработку персональных данных при регистрации

### 8.2 Технические меры

- HTTPS везде — Let's Encrypt, авторенью через cron
- Медицинские данные шифруются at-rest (pgcrypto)
- Пароли: bcrypt с cost-factor 12
- SQL-инъекции: только ORM (SQLAlchemy), никакого raw SQL с пользовательским вводом
- XSS: sanitize всего пользовательского контента перед сохранением
- Регулярный бэкап БД: ежедневно → S3, retention 30 дней
- Раздельный доступ: врач видит только своих пациентов, клиника — только свою
- Rate limiting на все API-эндпоинты через Redis

## 11. Ключевые риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Клиники не хотят регистрироваться (проблема курицы и яйца) | Высокая | Первые 30 клиник — вручную с менеджером, 3 месяца бесплатно |
| Мало реальных отзывов на старте | Средняя | Email-кампания после приёма; приоритет врачам с отзывами |
| Нарушение ФЗ-152 | Средняя | Юрист для разработки политики; хостинг в РФ с первого дня |
| Высокий no-show rate | Высокая | Штраф за позднюю отмену + SMS-напоминания за 24 ч и 2 ч |
| Конкуренция с СберЗдоровье / Напоправку | Средняя | Нишевание: регион, лучший UX, бонусная программа |
| Взлом и утечка медицинских данных | Низкая | Шифрование at-rest, аудит-лог, penetration testing |
