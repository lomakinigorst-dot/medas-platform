# WEBSITE.md — Правила страниц MEDAS

> Применяется при работе со статичными маркетинговыми страницами MEDAS (med-as.ru).
> Для Next.js SaaS-приложения (saas.med-as.ru) — этот файл неприменим.

⚠️ Прочитай ПЕРЕД созданием каждой новой страницы. Нарушение = неправильный стиль = переделывать заново.

---

## 3 СЦЕНАРИЯ — ВЫБЕРИ ДО НАЧАЛА РАБОТЫ

### СЦЕНАРИЙ 1: Новая страница (не Tilda-копия)
**Скилл: `/web-design`**

1. Дать скиллу: URL образца (лучшая страница проекта) + задание (что за страница) + путь к `template.html`
2. Скилл создаёт `DESIGN.md` → подтверди / отредактируй → скилл генерирует HTML
3. Подключить `medas.css` в `<head>` новой страницы
4. Деплой → curl-проверка URL

### СЦЕНАРИЙ 2: Копия существующей страницы (один в один)
**Метод:** curl → очистка → деплой  
**Протокол:** Блок 0.8 в `CLAUDE.md`

### СЦЕНАРИЙ 3: Брендбук / обновление дизайн-системы
**Скилл: `/design-system`**

Дать: URL главной страницы проекта  
Результат: HTML дизайн-системы + брендбук  
Применять: при обновлении `medas.css`, согласовании с клиентом

## АРТЕФАКТЫ ПРОЕКТА

- `medas.css` — токены и компоненты (подключать в `<head>` каждой страницы)

## КРАСНЫЕ ЛИНИИ

❌ Создавать новую страницу (не копию) без запуска `/web-design`  
❌ Писать стили внутри страницы вместо `medas.css`  
❌ Использовать цвета/шрифты не из дизайн-токенов выше  
❌ Не подтвердить `DESIGN.md` перед генерацией HTML  
❌ Делать Tilda-копию через `/web-design` — только `curl` + clean  
❌ Загружать только `index.html` без `index.htm`  
❌ Делать «похожий стиль» вместо точного совпадения с дизайн-спекой
